# Проверка перед первым обновлением

Дата: 6 ноября 2026 года. Проверена версия `24a5897` с исправлениями аудита
и переходом на API2 MAX. Изменения в инструкции после этой проверки не меняют
Python-код, зависимости или Docker-образ.

## Что проверено

Репетиция выполнена в изолированных Docker-контейнерах с `--network none`.
Использовались настоящий SQLite, зависимости из локального набора wheel-файлов,
старые исходники загрузчика и реальные команды Git/pip. Внешние MAX, Telegram
и нейросеть заменены тестовыми ответами; токены и данные сервера не использовались.

Исходные версии:

- `7cc474c0022083c4ec451416967a7d374c249a8b` — до изменения ролей;
- `cb19192514f2aecca39a716377e4495c057908b8` — более поздняя версия.

Для каждого перехода созданы основная база и два пространства, прежние роли,
черновики с фотографиями, частичная публикация, публикация с неизвестным
результатом, опубликованный материал, незавершённое редактирование и очереди.

| Проверка | Результат |
| --- | --- |
| Принудительно проваленный тест нового выпуска | Старый загрузчик отклоняет обновление; коммит, базы и медиа не меняются |
| Штатная полная проверка тестов новым кодом через старый загрузчик | Обновление принимается на обеих исходных версиях |
| Первый запуск через прежний entrypoint | Проверенные сценарии проходят |
| Повторный запуск в новом образе | Данные, роли и результаты публикаций сохраняются |
| Первый запуск нового образа непосредственно на старых данных `7cc474c` | Миграции и проверенные сценарии проходят без промежуточного запуска старого entrypoint |
| Принудительный сбой первого запуска и автоматический откат | В отдельном сценарии восстановлены старый код и Pillow 12.1.1; старая версия запускается, базы целы |
| Резервное копирование и восстановление | SHA-256 всех 15 исходных файлов баз/медиа и содержимое тестового `.env` совпадают после восстановления для обеих версий |
| Перенос исходников через `git archive` внутри контейнера | Проверены 108 элементов архива; `.env`, `data` и `code` сохраняются, файлы для пересборки присутствуют |

При запуске проверялись:

- целостность трёх баз и чтение старых ролей как участников без разрушительной перезаписи назначений;
- восстановление незавершённого редактирования и сохранение изменений;
- блокировка публикации старой кнопкой без актуального подтверждения;
- публикация в MAX и Telegram, повторное использование подтверждения без повторной отправки;
- продолжение частичной публикации только в ещё не завершённое направление;
- сохранение медиа и блокировка автоматического повтора при неизвестном результате отправки;
- приём материала через устойчивую очередь и выполнение команды;
- выбор API2, наличие доверенного сертификата и включённая проверка TLS.

Выводы сценариев: `PILOT OK: first_start`, `PILOT OK: after_rebuild`,
`ROLLBACK OK: previous application starts with Pillow 12.1.1, original roles and intact databases`,
`ARCHIVE OK: 108 tracked entries`.

Это дополнение к проверкам самого выпуска: 470 тестов, Ruff, mypy и сборка Docker
описаны в [результатах исправлений](AUDIT_FIXES.md).
Новых ошибок Python-кода в этой репетиции не обнаружено.

## Что уточнено в установке

Для первого перехода рекомендуется держать основной бот остановленным между
скачиванием кода и пересборкой образа. Загрузчик и Git выполняются отдельными
контейнерами через `docker compose run --rm --no-deps --entrypoint ...`.
Это позволяет впервые запустить новый код сразу с новым загрузчиком, включая
его обработку ошибок установки зависимостей. Успешный запуск старого entrypoint
не проверяет его поведение при всех возможных сбоях pip или сети.

Команды с указанием пользователя и папки находятся в
[одноразовой инструкции пересборки](INSTALL.md#временно-пересборка-после-обновления-кнопкой).
Для дальнейших обычных обновлений Python-кода остаётся кнопка в MAX.

## Что остаётся проверить на VPS

Точный установленный у владельца коммит неизвестен. Доступа к VPS, его базам,
токенам и каналам нет. Репетиция вызывает настоящий код запуска и сервисов,
но заменяет цикл polling/фоновых задач проверочным сценарием; она не проверяет
живую доставку событий и ответы внешних сервисов.
Проверка TLS к настоящему MAX из облачной среды блокируется сетевой политикой.

Перед обновлением:

1. Завершите частичные публикации и вручную проверьте неизвестные результаты в каналах; не меняйте каналы во время перехода.
2. При остановленном боте сохраните `.env` и всю `data`, проверьте читаемость архива и скопируйте его вне VPS.
3. Проверьте свободное место для копии и сборки (`df -h .`, `docker system df`). Не удаляйте `data` или Docker volumes ради освобождения места.
4. Обновитесь и пересоберите образ по указанной инструкции. Продолжайте после загрузчика только при `[updater] ok` или `[updater] nochange`.
5. Проверьте логи, `/menu`, список людей, редактирование и один материал в обоих каналах. Фото, короткое видео и смешанный альбом проверьте в тестовом пространстве с отдельными каналами.

Отказ реального API, права ботов в каналах, доступность нейросети и особенности
существующих данных подтверждаются только этой проверкой на VPS.
