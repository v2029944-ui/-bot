# Посты из MAX в MAX и Telegram

Сотрудник отправляет боту **в личном чате MAX** фото, видео или альбом до 10 вложений с общей подписью.
Нейросеть готовит текст; проверяющие получают материал и текст в MAX.
Кнопка «✅ Опубликовать» запрашивает подтверждение. Только нажатие
«✅ Да, опубликовать» отправляет согласованный вариант в каналы MAX и Telegram.
«↩️ Отмена» оставляет пост на согласовании. После изменения текста подтверждение
старого варианта не действует. При неизвестном результате предыдущей отправки
бот дополнительно просит проверить канал перед повтором.

Под постом у проверяющего три кнопки: **«❌ Отклонить»**, **«✅ Опубликовать»**
и **«✏️ Изменить»**. Отклонение требует подтверждения и удаляет черновик вместе с файлами.
В меню «Изменить» доступны «Заново», «С комментарием», «Править самому» и «Длина поста».
Выбор длины сразу создаёт новый вариант для согласования:

- **Короткий** — примерно 150–300 знаков.
- **Средний** — примерно 300–800 знаков.
- **Подробный** — примерно 800–1500 знаков.

Длина сохраняется для этого поста и учитывается при следующем пересоздании.
Это ориентиры для нейросети: при нехватке исходных фактов текст может быть короче.
Выбор не меняет общие правила редакции. Новый вариант получают все проверяющие;
публиковать его нужно отдельным нажатием «Опубликовать». Кнопка «Назад» возвращает
к предыдущему меню без изменения текста. Старые сообщения сохраняют прежние кнопки;
обновлённое меню появится у вновь отправленного или пересозданного черновика.

В MAX доступны исправление текста, повторная генерация, комментарии, правила стиля,
пользователи, уведомления, пауза и управление ботом. Telegram по умолчанию только
публикует: не опрашивает входящие сообщения, не показывает меню и не отправляет
служебные уведомления. Старые роли Telegram в базе не используются.

Администратору MAX под каждым новым сообщением бота в личном чате добавляется
кнопка **«⚙️ Меню админа»** — она доступна и под последним ответом, и под постом
на проверку. Нажатие открывает меню управления и отменяет ожидание ввода правки,
комментария или правила. У сотрудников и согласующих без прав администратора
этой кнопки нет. В опубликованные посты она не добавляется. Ранее отправленные
сообщения не меняются; после обновления отправьте боту `/menu` для нового ответа.

В меню **«📋 На проверке»** показаны ожидающие посты: автор, дата, краткий текст и
кнопка открытия; список разбит на страницы. Время соответствует `NOTIFY_TZ`.
При отклонении можно выбрать «Нужны другие фото», «Нужно описание», написать свою
причину или отклонить без причины. Причина отправляется сотруднику даже в тихом
режиме. Уже частично опубликованный пост отклонить нельзя — сначала завершите
публикацию или подтвердите фактический результат в каналах.

После попытки публикации бот показывает отдельное сообщение со статусом по MAX
и Telegram. Кнопка **«Отправить в оставшиеся каналы»** пропускает уже успешные
отправки. При неизвестном результате сначала проверьте канал: если пост есть,
нажмите «Проверил: пост есть…»; если отсутствует — разрешите повторную отправку.
Когда оба канала подтверждены, файлы удаляются с сервера.

За оставшиеся сутки до удаления необработанного черновика бот один раз предупреждает
проверяющих (проверка каждые `REMIND_CHECK_SEC`, по умолчанию 5 минут). Само
предупреждение и открытие поста не продлевают срок хранения. Новая версия поста
начинает срок согласования заново. При выключенном боте своевременная доставка
предупреждения невозможна; просроченные материалы при запуске удаляются.

## Очередь материалов и восстановление

Входящие фото, видео и альбомы записываются в SQLite до подтверждения событий MAX.
Отдельный обработчик скачивает файлы и готовит посты, поэтому обработка нового
видео не блокирует получение нажатий кнопок. Повтор события с тем же ID сообщения
не создаёт новый черновик. Отдельно отправленные одинаковые фотографии считаются
разными материалами.

При временной ошибке бот делает до 8 попыток с возрастающей паузой. После этого
администратор получает уведомление и может повторить обработку через
**«📥 Обработка материалов»**. После перезапуска незавершённая обработка продолжается.
Если пост уже создан, повторяется доставка готового черновика без новой генерации.

Очередь хранит ссылку на исходное событие в `data/drafts.db`; скачанные оригиналы
временно лежат в `data/inbox`. Они нужны для повторов при сбое нейросети и удаляются
после обработки, публикации, отклонения или истечения срока очереди (7 дней с приёма).
После обработки из очереди удаляются исходный текст и ссылки; остаётся компактная
запись ID для защиты от дублей. Готовые файлы черновика хранятся по обычным правилам.
Если ссылка MAX истекла до первого успешного скачивания, потребуется повторная
отправка сотрудником. После аварии возможна повторная доставка сообщения на
согласование, но оно относится к тому же черновику. Команды и текстовые диалоги
не включены в постоянную очередь; после перезапуска незавершённую ручную правку
или ввод причины нужно начать кнопкой снова.

Запускайте один экземпляр бота на одну базу. Базу и каталог `data` нужно сохранять
между обновлениями. Сам webhook пока не включён: [как получить HTTPS-адрес и сколько это стоит](WEBHOOK.md).

## Настройка

При использовании AITunnel (`LLM_BASE_URL=https://api.aitunnel.ru/v1`) кнопка
«📊 Статус» и команда `/status` показывают актуальный баланс в рублях и бюджет ключа,
если API его возвращает. Используется существующий `LLM_API_KEY`, новых настроек
не требуется. При ошибке получения баланса остальная сводка остаётся доступной.
Проверка состояния нейросети по-прежнему выполняет небольшой запрос к модели.

Скопируйте `env.example` в `.env` и заполните локально, не добавляя токены в Git:

| Переменная | Назначение |
| --- | --- |
| `TG_TOKEN`, `TG_CHANNEL` | Токен Telegram и канал; бот должен иметь право публиковать |
| `MAX_TOKEN`, `MAX_CHANNEL` | Токен MAX и числовой ID канала с правом публикации |
| `MAX_APPROVERS` | Числовые ID проверяющих через запятую |
| `MAX_ADMINS` | Администраторы MAX; также могут согласовывать посты |
| `MAX_EMPLOYEES` | Сотрудники; настройте вместе с администраторами для ограничения доступа |
| `APPROVAL_PLATFORM=max` | Согласование в MAX |
| `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_BASE_URL`, `MODEL` | Провайдер нейросети, ключ, адрес API и модель |

Сотрудники и проверяющие должны сначала открыть чат с ботом в MAX.
Настройки `TG_APPROVERS`, `TG_EMPLOYEES`, `TG_ADMINS` в этом режиме игнорируются.
`PUBLISH_TO_ALL=1` не требуется: Telegram автоматически получает каждый пост из MAX.
Входящий интерфейс Telegram удалён. Старые TG_MODE и TG_DROP_PENDING больше не используются.

Фото обрабатывается как раньше. Для видео нейросеть получает подпись и подборку
кадров, без распознавания речи. Сам ролик преобразуется в MP4/H.264 и отправляется
проверяющим и в оба канала. По умолчанию лимиты — **49 МиБ и 180 секунд**
(`MAX_VIDEO_MB`, `MAX_VIDEO_SEC`); размер проверяется также после преобразования.
Не увеличивайте лимит сверх ограничения Telegram Bot API в 50 МБ.
Для одного поста можно выбрать **до 10 фото и видео вместе** и отправить их **одним сообщением MAX** с общей подписью. Порядок вложений сохраняется. Общий размер набора — до 100 МиБ; для каждого файла также действуют ограничения фото/видео.

Проверяющий получает весь набор с одним текстом и кнопками согласования в MAX. После подтверждения в MAX выходит сообщение со всеми вложениями, а в Telegram — медиагруппа. Если текст не помещается в подпись Telegram, он отправляется следующим сообщением. Нейросеть видит общую подборку всех фото и кадров видео. Правка текста и повторная генерация сохраняют состав альбома.

Отдельные сообщения сотрудников остаются отдельными постами и автоматически не объединяются. Если один файл не прошёл проверку, весь альбом отклоняется: исправьте файл и отправьте набор заново. Старые черновики с одним вложением продолжают работать; база обновляется автоматически при запуске.

Если публикация прервалась, сообщение в MAX укажет, какой канал уже получил пост.
Повтор пропустит успешно опубликованный канал. При неопределённом результате
(например, таймауте) бот попросит проверить канал и подтвердить повторную отправку.
После успешной или неопределённой отправки хотя бы в один канал менять текст и
пересоздавать пост нельзя: повторная публикация должна сохранить один вариант в обоих каналах.

## Запуск и проверка

В Docker: `docker compose up -d --build`. После изменения `.env`:
`docker compose up -d --force-recreate`.

Для разработки нужен Python 3.12:

```sh
python3 -m venv /workspace/venvs/postbot
/workspace/venvs/postbot/bin/python -m pip install -r requirements-dev.txt
/workspace/venvs/postbot/bin/python -m pytest -ra
# После заполнения настроек:
/workspace/venvs/postbot/bin/python main.py
```

ffmpeg поставляется с `imageio-ffmpeg`. Тесты используют подставные API и настоящую
обработку короткого видео; токены и публикация в реальные каналы для них не нужны.
Интеграцию с реальными MAX/Telegram следует проверить отдельно после настройки токенов.

Официальные материалы MAX: [создание ботов](https://dev.max.ru/help/chatbots/),
[кабинет](https://dev.max.ru/ui/), [документация](https://dev.max.ru/docs/),
[Bot API](https://dev.max.ru/docs-api/).
Форматы загрузки, видео и callback сверены с
[официальной OpenAPI-схемой](https://github.com/max-messenger/api-schema/blob/1a4a502fab096aa3a15d83d7ea95667ffb44d2ac/schema.yaml).
В частности, для входящего видео бот получает прямую MP4-ссылку через
`GET /videos/{videoToken}`, затем скачивает файл с проверкой размера.

## Хранение фото и видео

После успешной публикации во всех подключённых каналах бот удаляет локальные фото,
видео, превью, текст поста, исходную подпись, данные автора и подробные отметки по
каналам. Посты в MAX и Telegram остаются. В базе сохраняются ID черновика, ключ
исходного сообщения, статус «опубликован», платформа и дата для статистики и защиты
от дублей. Пока публикация не завершена, текст, файлы и результаты отправки по
каналам сохраняются для повторной попытки.

Опубликованные тексты больше не используются как примеры для нейросети. Отдельные
правила редакции сохраняются. При первом запуске обновлённой версии очищается также
содержимое старых опубликованных записей. Итоговый статус каналов показывается
проверяющему перед тем, как эти сведения перестают использоваться; в чате он остаётся.

Необработанные черновики хранятся по умолчанию 7 дней с последней отправки на согласование (или с создания, если ещё не отправлялись). Затем они закрываются, а файлы удаляются при очередной очистке: при запуске и каждые 6 часов. При обновлении также очищаются оставшиеся файлы уже опубликованных постов.

**Для существующей установки:** в `.env` замените `DRAFT_TTL_DAYS=30` на `DRAFT_TTL_DAYS=7`. Обновление кода не меняет ваш `.env`. На сервере под `bot`, из `~/post_bot`, примените настройки командой `docker compose up -d --force-recreate`, затем обновите код выбранным способом. Если срок уже превышен, файлы будут удалены при ближайшей очистке.
