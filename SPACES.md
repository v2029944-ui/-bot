# Независимые пространства в одном боте

Один бот MAX и один бот Telegram могут обслуживать несколько независимых команд.
Работа сотрудников и проверяющих остаётся в личном чате MAX; Telegram только публикует.

У каждого нового пространства есть владелец MAX, отдельная группа MAX и отдельная
группа Telegram. Владелец может сам отправить материал, получить текст, исправить
его и подтвердить публикацию в обе свои группы. Другие владельцы не получают его
черновики и не могут управлять ими.

## Первое обновление

Обновите код обычной кнопкой или по INSTALL.md. Новых обязательных переменных `.env`
нет. Должны быть настроены оба бота и `MAX_ADMINS` главного администратора.
Перед обновлением сделайте резервную копию `.env` и всей папки `data`.
При обновлении кнопкой дождитесь окончания двухминутной проверки запуска:
до её завершения создание новых пространств временно недоступно.
Существующие данные и группы сохраняются как **основное пространство №0**.
Ничего из старой базы автоматически не переносится в новые пространства.
После назначения собственного пространства обычный владелец больше не получает
черновики основного пространства и не может использовать его старые кнопки.
Исключение — главные администраторы, сохраняющие полномочия основного пространства.

## Создание пространства

Главный администратор из `MAX_ADMINS` открывает в MAX:

`/admin` → «🏢 Рабочие пространства» → «➕ Создать пространство».

В ответ отправьте четыре строки, заменив пример настоящими значениями:

```text
Компания Иванова
123456789
-987654321
-1001234567890
```

Это название, ID владельца **в MAX**, ID группы MAX и ID группы Telegram.
ID пользователя Telegram вместо ID MAX не подходит. Один владелец получает одно
собственное пространство; группы нельзя повторно назначить другому пространству.
Существующие группы основного пространства также не следует использовать повторно.
Для групп, заданных через разные формы ID/username, проверьте отсутствие дубля вручную.

Добавьте тех же ботов в обе целевые группы с правами отправки фото, видео и постов.
Создание пространства сохраняет привязки; права в удалённых группах проверяются
фактической публикацией. Сначала используйте тестовые группы и материал.
Владелец должен открыть личный чат с ботом в MAX; после создания отправляет `/myspace`.

## Настройки владельца

У пространства отдельные правила редакции, ссылка и маркер `{bot}`, режим сравнения
моделей, черновики, результаты отправки, пользователи и расписания уведомлений.
Название пространства используется как название компании в базовой инструкции
нейросети. Модель по умолчанию и технические настройки берутся из общего `.env`.

Через «➕ Добавить человека» владелец может отправить две строки:

```text
123456789
проверяющий
```

Вторая строка — `проверяющий` или `сотрудник`. Роли и удаление добавленных людей
управляются в «Люди». Владелец остаётся администратором своего пространства.
Пауза действует только на выбранное пространство и не останавливает остальные.

Если человек участвует в нескольких командах, нажатие кнопки сообщения выбирает
соответствующее пространство для следующих текстовых ответов. `/myspace` возвращает
владельца в своё собственное пространство; `/admin` возвращает главного администратора
в основное. Обычные владельцы не могут обновить общий процесс бота или создать чужое
пространство. Главный администратор не получает копии всех чужих постов автоматически.
В меню и подтверждениях показывается название выбранного пространства.

## Хранение и расходы

Основная база остаётся в `data/drafts.db`. Каждое новое пространство хранится в
`data/spaces/НОМЕР/`: отдельная SQLite-база, фото, видео и временные файлы.
Постоянный Docker-том `data` уже включает эти папки. Резервная копия должна включать
**всю** папку `data`, а также `.env`. После перезапуска привязки и базы сохраняются.

Очереди получения событий общие, а обработка выполняется в контексте нужной команды.
Кнопки содержат номер пространства, поэтому одинаковый ID черновика в двух базах
не даёт доступ к другому посту. Очистка файлов и сроки хранения действуют отдельно.
В «Обработка материалов» владелец видит только ошибки своей команды; главный
администратор в основном пространстве видит общую очередь.

Ключ AITunnel и токены ботов общие. Все команды расходуют **один баланс AITunnel**;
баланс в статусе доступен только в основном пространстве. Полномочия на сервере и
доступ к резервным копиям остаются у владельца VPS. В этой версии создание и
добавление участников доступны через меню; перенос существующего пространства
другому владельцу и смена его групп через меню ещё не предусмотрены.
