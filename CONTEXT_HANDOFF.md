# Контекст для продолжения разработки

Проверенная версия `main`: `5fb76de` (6 ноября 2026). Эта ветка временная: файл нужен после перезапуска Codex, переносить его в рабочий `main` не требуется.

## Проект и ограничения

- Репозиторий: `v2029944-ui/-bot`. Python 3.12, SQLite, HTTPX; Telegram через aiogram только публикует. Все рабочие действия пользователей — в MAX. Точки входа: `entrypoint.sh`, `main.py`; бизнес-логика — `services/`, совместимый интерфейс — `core.py`.
- Пространства изолированы: №0 — `data/drafts.db`, остальные — `data/spaces/<id>/`. Контекст переключает `spaces.py`. Не нарушать проверки автора/роли, namespace кнопок, версии/nonce подтверждений и снимков каналов публикации. При unknown/partial отправке автоматический повтор запрещён до решения человека.
- Главный администратор задаётся `MAX_ADMINS` в `.env`; администратор пространства и участник — отдельные права. Сохранённые в БД реквизиты №0 имеют приоритет над начальными ID из `.env`. Роли, черновики и базы при обновлении сохранять; миграции аддитивные, совместимость проверяется `compatibility.json`.
- Выбор 1–4 компактных моделей AITunnel, разрешённый список — `comparison.BUDGET_MODELS`. Дорогие модели без просьбы пользователя не возвращать.
- Пользователь разрешил исправления и публикацию на GitHub. Замечание F12 о синхронизации документации просил оставить: старые отчёты и отдельные утверждения `ARCHITECTURE.md` могут быть неактуальны; сверять с кодом.

## Скиллы и официальные источники MAX

- В облачной среде сначала читать `cloud-environment:cloud-environment-runtime` через `skills.list/read`: состояние среды, политика сети, Docker, прокси и CA. `cloud-environment-onboarding:setup` — для настройки новой среды, не для каждой правки бота.
- Для MAX использовать официальный скилл [max-messenger](https://github.com/max-messenger/max-agents-skill). В текущей среде: `/home/agent/.agents/skills/max-messenger/SKILL.md`; копия также в `/workspace/skills/max-agents-skill/`. В новой среде наличие проверить. Для Python/raw HTTP читать `references/bot-api.md`, `objects-and-updates.md`, `tls-trust.md`, при работе с кнопками/текстом — `formatting.md` и `patterns.md`.
- Документация: https://dev.max.ru/docs-api/ ; официальная OpenAPI-схема: https://github.com/max-messenger/api-schema . Последняя сверенная ревизия схемы — `1a4a502fab096aa3a15d83d7ea95667ffb44d2ac`; при изменении API проверять актуальную.
- MAX: `https://platform-api2.max.ru`, заголовок `Authorization: <token>` без Bearer. Текст до 4000 символов. Загрузка через URL из `POST /uploads`; `attachment.not.ready` требует ожидания. Видео скачивается через `GET /videos/{token}` и `urls.mp4_*`.
- `max_tls.py` добавляет закреплённый корневой CA из `certs/` только клиенту MAX. Никогда не отключать TLS-проверку. Сейчас используется long polling; webhook ещё не реализован, хотя MAX рекомендует его для production.
- Облачная сеть блокировала dev.max.ru, живые MAX/Telegram/AITunnel. Официальная схема доступна через GitHub. Каталог/баланс AITunnel и права реальных каналов не считать подтверждёнными mock-тестами. Токенов и доступа к VPS здесь нет.

Sandbox этой среды может блокировать даже минимальный `asyncio.to_thread`: при таком зависании проверять в Docker или разрешённом локальном исполнении, не менять логику бота без воспроизведения вне ограничения. Для облачной Docker-сборки CA прокси передавать временно по инструкции runtime-скилла; не коммитить его и не отключать TLS.

## Применение на VPS — требуется пересборка Docker

**Установка последней версии на VPS не подтверждена. Одной кнопки обновления недостаточно:** она обновляет `/app/code`, а `entrypoint.sh` вызывает загрузчик `/app/updater.py` из образа. Изменение загрузчика в `5fb76de` применяется только после пересборки.

- Команды пользователя: Linux-пользователь `bot`, каталог `/home/bot/post_bot`. Сначала проверить частичные/неизвестные публикации и сделать резервную копию `.env` и всей `data` при остановленном боте.
- Остановить бот, штатным отдельным контейнером обновить `code`, проверить `[updater] ok`/`nochange`. Затем перенести **все отслеживаемые исходники** из обновлённого `code` в каталог сборки через `git archive`, сохранив `.env`, `data`, `code`. Простая сборка старой папки нужный загрузчик не доставит.
- Далее: `docker compose build bot`, после успеха — `docker compose up -d --force-recreate bot`, проверить логи, меню, роли и материал в тестовых группах.
- Точные команды уже есть в [INSTALL.md, «Временно: пересборка после обновления кнопкой»](INSTALL.md#временно-пересборка-после-обновления-кнопкой). Не удалять этот раздел до подтверждения пересборки пользователем.
