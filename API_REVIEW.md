# Проверка MAX и Telegram после обновления интерфейса

## Повторная проверка пространств — 5 ноября 2026

Актуальные находки и исправления описаны в [MAX_API_REVIEW.md](MAX_API_REVIEW.md).
Повторно сверена официальная схема MAX из `max-messenger/api-schema`:
`1a4a502fab096aa3a15d83d7ea95667ffb44d2ac`; после обновления репозитория новых
изменений схемы нет. Сайт dev.max.ru недоступен в этой облачной среде.

Исправлены маршрутизация быстрого ответа на кнопку между пространствами,
влияние группового `/menu` на личную правку, скрытие ошибок от очереди,
уведомления об истечении срока в чужую команду, обработка `success=false`
при HTTP 200 и накопление завершённых блокировок отправки.

Описания ниже фиксируют результаты прошлых проверок. Команды и callback теперь
имеют постоянную очередь SQLite; ожидание ручного ввода сохраняется только в памяти.

## Повторная проверка версии 4db08dd

После добавления фоновых команд, встроенного меню и ссылки в черновиках выполнена
повторная проверка. Полный набор: **318 тестов прошли**.

Исправлены три дополнительные ошибки:

- Планировщик читал тела всех ожидающих команд. Теперь индексированная выборка
  получает только первые команды отдельных пользователей, не более восьми
  кандидатов для четырёх рабочих мест. Большая очередь одного пользователя не
  мешает запланировать команду другого.
- Неожиданное исключение обработчика могло оставить запись в `processing` до
  перезапуска. Теперь команда помечается как неудачная, её содержимое очищается,
  пользователю отправляется уведомление. Неизвестный побочный эффект не повторяется
  автоматически; отменённые при остановке команды остаются для восстановления.
- Команда `/rules` могла отправлять неограниченный список, а меню ограничивало
  длину без учёта эмодзи. Теперь используется ограниченное представление с пределом
  по UTF-16, соответствующим консервативным ограничениям обоих адаптеров.

Повторно проверены: HTML-ссылка в варианте на согласование и публикации,
фиксирование ссылки за версией, отсутствие дублирования, изменение клавиатуры
без перезаписи форматированного текста, альбомы, подтверждения публикации,
очистка старых клавиатур и отправка только в оставшиеся каналы.

Официальная схема MAX повторно обновлена: её ревизия осталась
`1a4a502fab096aa3a15d83d7ea95667ffb44d2ac`. Сайты MAX и Telegram при повторных
запросах снова недоступны через прокси (403). Источники и ограничения проверки
описаны ниже. Работа с реальными токенами и каналами не выполнялась.

Ниже сохранён отчёт предыдущего этапа проверки интерфейса.

Проверена версия пользователя `a6ca9c3` и внесённые по результатам исправления.

## Источники и границы проверки

- Официальная [схема MAX](https://github.com/max-messenger/api-schema/blob/1a4a502fab096aa3a15d83d7ea95667ffb44d2ac/schema.yaml), обновлена перед проверкой.
- Официальная [реализация Telegram Bot API](https://github.com/tdlib/telegram-bot-api/blob/master/telegram-bot-api/Client.cpp), получена во время проверки.
- Контракты методов установленного aiogram: sendPhoto, sendVideo, sendMessage и sendMediaGroup.
- Ссылки на документацию: [MAX](https://dev.max.ru/docs-api/), [Telegram](https://core.telegram.org/bots/api).

Сайты документации недоступны из среды проверки (HTTP 403). Сверка MAX выполнена
по официальному репозиторию схемы; для Telegram дополнительно использованы исходники
сервера и описание ограничений методов в aiogram. Это не проверка действующего
бота с токенами: реальные каналы не использовались.

## Исправления

1. **Неверное расположение исходного сообщения callback MAX.** В официальном
   `MessageCallbackUpdate` поля `callback` и `message` находятся на одном уровне.
   Теперь адаптер передаёт исходное сообщение обработчику; логика удаления экранов
   может определить, под каким сообщением нажали кнопку. Учтён `message=null`.
2. **Скрытая копия текста в `max_ui`.** Новая логика переноса кнопки хранила текст
   и вложения независимо от очистки опубликованного черновика. Теперь локально
   сохраняется только ID сообщения. Для редактирования клавиатуры актуальное
   сообщение запрашивается через `GET /messages/{messageId}`. При запуске старые
   копии текста из таблицы интерфейса удаляются. Клавиатура заменяется вместе с
   сохранением текущего текста и токенов медиа, как требует контракт PUT /messages.
3. **Одновременные уведомления одному администратору.** Отправка служебных сообщений
   одному получателю выполняется последовательно, чтобы перенос кнопки не оставлял
   несколько активных кнопок из-за одновременной отправки.
4. **Слишком узкие фотографии для Telegram.** Нормализация ограничивала размер,
   но не отношение сторон. Теперь снимки с отношением более 20:1 получают белые
   поля до допустимой формы. Обрезка содержимого не выполняется.

## Ограничения, которые остаются

- MAX рекомендует webhook вместо long polling для постоянной эксплуатации.
  По решению пользователя webhook пока не включён.
- Материалы, текстовые команды и callback имеют постоянные очереди.
  Ожидание ручного ввода теряется при перезапуске; повтор уведомления проверяющему
  после аварии возможен.
- Удаление старого меню или редактирование кнопки может быть отклонено сервисом.
  Ошибка логируется; поэтому строго гарантировать единственную видимую кнопку
  при сетевом сбое нельзя.
- После получения токенов нужны реальные проверки смешанных альбомов, прав бота,
  отображения клавиатур и повторной публикации после сетевого сбоя.

Новые регрессии проверяют формат callback, отсутствие содержимого в таблице
интерфейса, перенос кнопки при одновременных уведомлениях и панорамные фото.
Полный набор: **295 тестов прошли** перед публикацией исправлений.
